Personal Projects


Doma


My main personal project, which I work on infrequently when I have time, is a flashcard website aimed at language learners. I am hoping to deploy this website (and eventually app) as a tool that focuses on strategies that benefit language learning in particular, as opposed to memorization. The website is a work in progress; next steps include:


  • adding user logins
  • adding a database
  • cleaning up website - visual appeal and accessibility
  • implementing security features


In the long term, I also want to implement more games and practice methods, including matching games and some vocab-specific games (eg a paint-by-number for practicing color words, counting games, etc). This is a long-term passion project I hope to work on and eventually deploy as a real resource. I am trying to learn some languages myself, and found myself primarily enjoying resources that have since become paywalled, and I am interested in recreating them for myself and adding to them in ways that actually support language learners based on research describing best practices in language education as well as input from real people.



SongGuess


This web game was inspired by Wordle and its offshoot, Heardle. I like to play these kinds of games when getting together with friends. While playing some of the Heardle variations that allow a user to select a genre or category of music, I found myself thinking about a version that pulls music directly from the user's own library. I realized I could make it and spent the summer of 2026 working on this alongside other projects. I had a lot of fun making this website, especially as it was my first experience working directly with any API. I learned a lot, particularly about how to navigate network requests and responses.

This game is coded entirely in HTML, CSS, and JavaScript. It uses Spotify's API to log the user in, select one of their playlists at random, and select a random song from said playlist. Then, it enables user input for the first input section. The user may then guess a song. For now, I have coded the game so that it performs a query and submits a song based on whatever the user typed (excluding a null response, in which case the response is discarded and the next input section becomes available). The song selected by the query is checked against the answer, and the user either wins or moves on to the next clue.
